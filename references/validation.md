# 验证与验收

验证结果分为通过、失败、未执行/待试听，不以静音文件存在或脚本退出0替代结果检查。只补充与具体失败有关的验证。

| 层 | 应检查的内容 | 证明范围 |
|---|---|---|
| 原曲 | 底稿来源、版本、调性/移调、段落、重复、弱起和名义旋律事件；primary覆盖、冻结hash | 后续编配保持审校基准，不独立证明基准100%转写正确 |
| 配器 | 实音音域、单音/复音、和声约束、斜线低音、非和弦音说明、实际并发/家族参与、高潮发展 | 音乐规则成立；不同风格用不同规则 |
| 表演/MIDI | on/off配对、重复音/重叠、端口/通道/program/CC/奏法键、微时序与gate映射 | 指令与表演方案相符；MIDI不证明音色 |
| 渲染 | 无缺样本/include、错误、NaN、非预期静音、漏音/截尾；格式、长度、音准/CC探针 | 后端和映射实际工作 |
| 混音 | 实际轨/家族/段落能量、频谱遮挡、sample/true peak、LUFS、mono/相关、编码后检查 | 测量成立；不能自动证明宏大或好听 |
| 分轨 | 重读打印轨与FX，按声明重建premaster；非线性master另算 | 交付可重混；不能把总bus重复加一次 |
| 乐谱 | 音高/名义时值、voice、连线、拍号、和弦拼写/转调、每页渲染 | 可编辑且音乐/视觉一致 |
| 复现 | 新位置映射root、完整资产hash、环境/工具/种子、代表段重渲染 | 已验证平台和后端范围内复现 |

对旋律核对使用事件ID/多重集合和名义时值，不只数note-on。同音重复和真实长音重叠保留；奏法键、鼓、FX不算旋律，连线拆出的谱面音头不等于新增攻击。

密度统计须报告是否按拍或按秒加权，排除鼓、控制键和纯reverb尾音；同时说明活跃部件数与音符数。风格目标可转成段落参与/能量等可测试约束，但阈值来自当前brief，不能强迫每首歌都有三次递增副歌。

试听选能暴露问题的段落：主题初入、最稀疏段、最密集段、过渡、低频强段、高音合奏和结尾。用户已给具体反馈时优先处理对应位置。记录A/B响度匹配、修改层和剩余不确定性。缺少实际试听渠道时交付可播放预览并如实报告，不能冒充耳朵验收。

## 随附工具的实际覆盖

`project.py`核对基本结构、source-primary覆盖/音高/名义时值、锁定底稿、声明的音域/复音/和声约束及密度。它不自动审查所有乐理规则或陌生schema扩展。`audio.py`检查有限值、静音、峰值、4x估计真峰值、RMS/相关，ffmpeg可用时加LUFS测量；mixer重读分轨验证重建。正式成品还需按上表补齐未覆盖项。

`tests/test_pipeline.py`使用原创数据验证不同调性与风格映射、变速/变拍、旋律破坏检出、跨目录hash、随机种子确定性、实际渲染及mix重建。它验证通用工具，不证明任意歌曲都能自动转写，也不构成审美保证。测试输出在临时目录，不能污染歌曲工程。
