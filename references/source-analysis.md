# 输入与歌曲底稿

## 根据输入选路线

- MusicXML/可编辑总谱：解析调号、移调乐器、反复、弱起、连线、多voice和速度变化；展开真实演奏路线，用音频核对版本差异。
- MIDI：读所有轨、端口、通道、tempo、meter、program和note-on/off。确定实音、旋律、伴奏和控制键；连奏gate与扫弦微时序不直接当谱面节奏。
- PDF/图片谱：检查整页和低置信度符号，保留谱面小节锚点。指法谱、capo、移调乐器和实际调性分别记载。
- 原唱/伴奏音频：探测真实容器、采样率、声道、时长与损坏。提取onset/beat/chroma，必要时分离人声/低音/鼓；对目标线条用适合音域的F0或复音转写器。分离轨的标签不是它含有真实歌唱的证据。

一般工具为ffprobe/ffmpeg、librosa、经验证的分离器与音高识别器。先查询当前环境实际CLI/API，不能猜模型调用。保存模型版本、权重哈希、重采样、hop、置信度、音域和命令；估计的速度/调性/和弦只是候选。

## 审校

确认实际版本（专辑/单曲/现场可能不同），局部调性、速度/拍号变化、拍点与音频偏移、弱起、反复顺序、段落边界、旋律重击、长音与接句重叠、和弦变化拍、转位低音和结束/淡出。相同音高的多次起音保存为不同事件。原唱滑音按任务决定存为表达数据或注明未转写。

保存不确定乐句的谱面/音频锚点、候选与修正依据。可先对可信区段编配；扩编不确定主题之前针对性复核。资料不足时明确保真范围，不能编造已校正的全曲转写。

## 和弦与实音

分开保存`source_label`（原谱标记）、`concert_symbol`（实音符号）、`pcs`（实音pitch classes）、`bass_pc`（转位低音）。capo/乐器移调只应用一次。和弦质量、功能变化与斜线低音随底稿冻结；用户要求再和声时保存原和声、新和声及映射，更新验证器，不静默覆盖基准。

通用JSON音高是12平均律整数MIDI。微分音、连续弯音或复杂自由节奏可使用DAW/扩展格式，但记录扩展和验证方法，不能静默量化后声称精确保真。

原曲证据与风格参考分别列出。参考编配不自动成为本歌原曲事实。查找乐谱或音源时保存出版方/作者来源和具体版本，不能凭搜索标题推断完整谱内容。歌曲、采样库和代码分别记录许可，不相互套用。
